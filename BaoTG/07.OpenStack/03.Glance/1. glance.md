# TÌM HIỂU VỀ SERVICE GLANCE TRONG OPENSTACK
## Glance là gì ?
- Trong hệ sinh thái OpenStack, Glance là Dịch vụ Hình ảnh (Image Service). Nếu ví OpenStack như một nhà máy sản xuất máy tính, 
thì Glance chính là "kho chứa đĩa cài đặt hệ điều hành" (như đĩa chứa Ubuntu, CentOS, Windows) để sẵn sàng cung cấp cho người 
dùng bất cứ lúc nào.

## Chức năng của Glance
- *Lưu trữ và quản lý Image*: Glance cho phép người dùng tải lên (upload), đăng ký, lưu trữ và tìm kiếm các tệp ảnh đĩa ảo (ví dụ
định dạng .qcow2, raw, vmdk). Các file này chứa sẵn hệ điều hành và các phần mềm cấu hình sẵn.
- *Cung cấp Image cho Nova*: Khi bạn ra lệnh tạo một máy ảo mới trên Nova, Nova sẽ liên lạc với Glance để tải hoặc trích xuất bản
image tương ứng nhằm khởi tạo ổ đĩa cho máy ảo đó.
- *Quản lý siêu dữ liệu (Metadata)*: Glance không chỉ lưu các tệp nhị phân của hệ điều hành mà còn lưu trữ các thông tin mô tả chi tiết (metadata) như: kích thước file, định dạng, hệ điều hành gì, dung lượng RAM tối thiểu yêu cầu là bao nhiêu, v.v.

## Các thành phần trong Glance
Glance được cấu thành từ các module và thành phần chính sau:
- glance-api (Cổng giao tiếp dịch vụ):
+ Chức năng: Là thành phần nhận tất cả các yêu cầu HTTP/REST API từ người dùng hoặc từ các dịch vụ khác (như Nova, Horizon) gửi 
tới.
+ Nó chịu trách nhiệm xử lý việc đăng ký metadata, thực hiện các thao tác tải lên (upload), tải xuống (download) các file image.

- glance-registry (Dịch vụ quản lý thông tin - lưu ý: từ các phiên bản gần đây đã được tích hợp trực tiếp vào Glance API hoặc 
database):
+ Chức năng truyền thống: Chuyên lưu trữ, xử lý và truy vấn các thông tin siêu dữ liệu (metadata) liên quan đến image trong cơ sở
dữ liệu.

- Glance Database (Cơ sở dữ liệu):
+ Chức năng: Lưu trữ toàn bộ bảng thông tin, định danh, trạng thái, quyền riêng tư (public/private/shared) và metadata của các 
image.

- Glance Backend Stores (Kho lưu trữ vật lý):
+ Chức năng: Đây không phải là một tiến trình mã nguồn mà là nơi lưu trữ thực tế các file nhị phân của image. Glance cực kỳ linh 
hoạt vì hỗ trợ rất nhiều loại kho chứa khác nhau như:
+ Lưu trực tiếp trên ổ đĩa cục bộ (File system).
+ Lưu trên Object Storage (Swift).
+ Lưu trên cụm lưu trữ phân tán Ceph (RBD).
+ Hoặc các dịch vụ lưu trữ ngoài như Amazon S3.

## Địng dạng image được hỗ trở bởi Glance
### Định dạng đĩa
- Định dạng đĩa là cấu trúc của tệp ảnh đĩa ảo gốc của máy ảo (tương ứng với cách mà hypervisor đọc hiểu dung lượng và dữ liệu ổ cứng):
+ raw: Định dạng đĩa thô, không có cấu trúc phức tạp. Nó tương đương với việc bạn sao chép trực tiếp từng khối dữ liệu (giống lệnh dd trên Linux) và được hỗ trợ nguyên bản bởi cả KVM lẫn Xen.
+ qcow2: Định dạng chuẩn rất phổ biến thường đi kèm với hypervisor KVM/QEMU. Nó hỗ trợ tính năng cấp phát động (dung lượng file nhỏ gọn hơn) và cơ chế Copy-on-Write.
+ vhd: Định dạng ổ cứng ảo (Virtual Hard Disk) quen thuộc được sử dụng bởi các trình quản lý ảo hóa từ Microsoft, Xen, VirtualBox, VMware.
+ vhdx: Phiên bản nâng cấp của định dạng VHD, hỗ trợ dung lượng ổ đĩa lớn hơn và có cơ chế bảo vệ chống hỏng dữ liệu khi mất nguồn đột ngột.
+ vmdk: Định dạng ổ cứng ảo phổ biến do VMware phát triển, được sử dụng rộng rãi trên các hệ thống VMware ESXi.
+ vdi: Định dạng ổ đĩa ảo được sử dụng bởi phần mềm ảo hóa VirtualBox và trình giả lập QEMU.
+ iso: Định dạng lưu trữ ảnh đĩa quang (CD/ROM) ở chế độ chỉ đọc.
+ ploop: Định dạng đĩa được sử dụng bởi Virtuozzo để chạy các hệ điều hành dạng Container.
+ ami, ari, AKI: Các định dạng ban đầu bắt nguồn từ hệ thống Amazon EC2 (tương ứng với Amazon Machine Image, Ramdisk Image và Kernel Image).
### Định dạng vùng chứa
- Định dạng vùng chứa biểu thị việc tệp image có được đóng gói kèm theo siêu dữ liệu (metadata) bổ sung về máy ảo hay không:
+ bare: Đây là định dạng phổ biến và mặc định nhất. Nó biểu thị rằng file image không có bất kỳ lớp bọc hay vùng chứa meta nào cả (chỉ có file dữ liệu đĩa thuần túy).
+ ovf: Định dạng OVF (Open Virtualization Format) do tổ chức tiêu chuẩn DMTF định nghĩa, gói gọn mô tả XML cấu hình máy ảo cùng với các file đĩa.
+ ova: Định dạng gói OVF được nén dưới dạng một file lưu trữ tar đơn lẻ.
+ docker: Định dạng tệp lưu trữ tar của hệ thống tệp container Docker.
+ ami, ari, AKI: Các định dạng vùng chứa dùng riêng cho các image kiểu Amazon.

## Quy trình hoạt động của Glance
Quy trình hoạt động của Glance trải qua hai giai đoạn chính: Tải image lên hệ thống và Sử dụng image để tạo máy ảo.
**Quy trình 1: Tải một Image mới lên hệ thống (Upload Image)**
+ Gửi yêu cầu: Người dùng gửi yêu cầu tạo image mới (kèm theo file .qcow2 và thông tin metadata) tới glance-api.
+ Xác thực: Glance-api gọi sang Keystone để xác thực xem người dùng này có quyền tạo image hay không.
+ Lưu Metadata: Glance-api lưu các thông tin mô tả image vào Glance Database.
+ Lưu file nhị phân: Dữ liệu nhị phân của tệp ảnh đĩa được Glance-api chuyển tiếp và lưu trữ vào kho chứa Backend Store (ví dụ như vào Ceph hoặc thư mục lưu trữ cấu hình).
+ Hoàn tất: Trạng thái của image chuyển sang active và sẵn sàng để sử dụng.

**Quy trình 2: Sử dụng Image để tạo Máy ảo (Boot Instance)**
+ Yêu cầu từ người dùng: Người dùng ra lệnh cho Nova tạo một máy ảo mới bằng cách chọn một image cụ thể.
+ Gọi Glance API: Nova gửi yêu cầu tới glance-api để lấy đường dẫn hoặc tải file image đó về.
+ Kiểm tra quyền: Glance kiểm tra xem image này ở trạng thái public, private hay shared xem người dùng có quyền dùng nó hay không.
+ Truyền tải dữ liệu: Glance cung cấp dữ liệu image từ Backend Store cho Nova Compute để Nova dựng lên ổ đĩa của máy ảo chuẩn bị khởi động.
